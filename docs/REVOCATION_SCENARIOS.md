# 撤销、退出与设备停用：场景说明

版本：2026-09-16。本版已实现账号、审批设备管理与区分发起人的撤销审计；恢复机制与通用委托仍属后续工作。

## 面向用户的术语

| 操作 | 发起人及证明 | 停止什么 | 保留什么 | 当前状态 |
| --- | --- | --- | --- | --- |
| 用户撤销 Agent 关系 | 用户审批端确认，由用户密钥签名 | 该关系的后续申请与执行；旧授权不能绕过关系状态 | 原请求、决策和执行回执 | 已实现，记录 user_revoked 与签名证据 |
| Agent 退出关系 | 该 Agent 自己签名 | 自己这条关系的后续使用 | 用户历史记录、其他 Agent 关系 | 已实现，记录 agent_withdrawn 与签名证据 |
| 撤销某项长期委托／暂停自动规则 | 有管理权的用户签名 | 该规则或委托的后续自动授权 | Agent 关系、其他规则与历史回执 | Demo 已有暂停规则；通用委托待扩展 |
| 撤销审批设备 | 其他有管理权的已登记设备确认 | 该设备的登录、签署、管理能力及其所有活动配对关系 | 用户账号、未被撤销的其他设备 | 已实现，记录 device_revoked |
| 退出登录 | 当前浏览器结束账号会话 | 当前会话继续访问账号数据 | 服务端关系、设备登记及本地密钥；重新登录后恢复本设备权限 | 已实现 |
| 清除浏览器数据 | 浏览器操作 | 可能丢失本地密钥与记录访问能力 | 服务器状态不会因此自动撤销 | 现有风险；不能把清除数据当作安全撤销 |
| 丢失唯一审批设备 | 已预设的恢复方式验证用户 | 先冻结失窃设备，恢复新的管理设备 | 尽可能保留账号及可验证历史 | 待设计恢复策略，不能仅凭账号名称恢复签名权 |
| 新建配对 | 双端用户确认 | 不自动停止任何旧关系 | 旧关系直到明确撤销或过期 | 已实现，重新配对不隐含撤销 |

## 场景与提示文案

### 用户不再使用某个 Agent

提示：“撤销后，该 Agent 不能再使用这条关系申请或执行。已完成的操作不会被撤回，历史回执保留。”

用户确认后记录 `user_revoked`，包含关系ID、操作人密钥指纹、时间、原因及签名证据。需在执行时重新检查状态，不能只检查授权签名。

### Agent 卸载、迁移或主动退出

提示：“此 Agent 已退出关系。该操作由 Agent 发起，并非用户在手机上的撤销决定。”

记录 `agent_withdrawn`。退出只能减少该 Agent 的权限，不能撤销其他 Agent 或用户设备，不能自行恢复。新关系仍需用户确认。

### 只停止自动批准，仍希望收到人工申请

提示：“暂停这条自动规则后，新请求需要人工决定；Agent 绑定保持不变。”

区分停止规则与撤销整个关系。已经签发但未使用的授权，应按明确的失效策略处理并在资源端复核，不能仅修改手机列表。

### 手机丢失，但还有已登记的 Mac

有设备管理权的 Mac 可以撤销失窃手机。只读 Mac 不得执行此操作。服务端拒绝失窃设备的后续会话与签名使用。用户应能看到哪些关系/委托由失窃设备管理，以及是否需要重新授权。

已实现管理设备的签名确认、服务端设备登记、在线权限检查和停用审计。此版本是 MYA 服务端验证的设备授权记录，不是可携带到任意业务系统的通用设备授权 VC。停用设备同时终止其活动关系，旧授权无法继续执行。

### 账号登录成功，但该浏览器还没有审批资格

提示：“已验证账号密码，此设备等待已有管理设备确认；确认前不显示账号目录。”

管理设备可赋予只读、审批或管理权限。只读设备看到目录；审批和管理设备也只能处理由本设备独立配对的关系，不能替原手机签名。

登录认证与审批资格分别校验，不能因为登录成功就把原手机私钥复制到新浏览器。

## 实施要求

- 撤销事件追加保存，不用覆盖一个状态字段代替审计。事件包含实际签名主体、对象、时间、原因和唯一事件号。
- 明确区分 `user_revoked`、`agent_withdrawn`、`device_revoked`、`expired` 与本地待同步状态。
- 手机离线操作立即本地停用；服务端确认前显示“等待同步”，不能声称远端已拒绝执行。
- 执行端检查最新关系、设备及委托状态；新挑战不能使已撤销授权重新有效。
- 对撤销与执行并发给出明确的事务顺序；已完成的执行只保留事实，不声称撤销能回滚。
- 原自动规则和请求内的业务信息属于受保护数据，不因共享账号而默认对所有设备公开。

# 账号登录与审批设备管理

## 首次使用与旧配对迁入

1. 在已有 WorkBuddy / Codex 配对的手机浏览器打开 https://mya-esand.duckdns.org/mobile/ ，刷新页面，选择「账号与设备」。不要清理浏览器数据。
2. 注册用户名、密码及设备名称。用户名为 3–48 个英文字母、数字、点、下划线或连字符；密码为 15–128 个字符。密码只在网页输入，不发给 Agent。
3. 原浏览器密钥保持不变，其既有关系会出现在账号目录中；首台注册设备成为管理设备。注册不会自动合并其他浏览器的身份。
4. 在 Mac 或另一部手机用同一账号登录，填写不同设备名称。此时为「待确认」，不能读取账号目录。
5. 回到原手机的「账号与设备」，确认新设备的名称和公钥指纹，授予所需角色。

## 三种设备角色

| 角色 | 查看统一 Agent 目录 | 审批 | 添加／停用其他设备 |
| --- | --- | --- | --- |
| 只读查看 | 可以 | 不可以 | 不可以 |
| 审批本设备关系 | 可以 | 仅本设备独立配对的关系 | 不可以 |
| 设备管理 | 可以 | 仅本设备独立配对的关系 | 可以 |

账号目录包含 Agent 名称、公钥指纹、关系状态、所属审批设备等元数据。审批正文、Review、自动规则及密钥仍在原浏览器；没有复制私钥，也没有跨设备继承旧关系签名权。因此目录相同，而待审批详情不同，是预期行为。

设备授权由原管理设备对新设备及其角色签名，服务端验证挑战、签名、当前管理权及账号归属并保存审计。这是本 Demo 的在线授权机制，不应声称已支持通用设备授权 VC 或任意第三方离线验证。

## 退出、停用与恢复

- 退出登录：结束会话，保留本地密钥和关系；本设备再次登录后恢复原有角色。
- 停用其他设备：需要管理设备签名，结束目标会话，终止其活动配对关系；此前批准但未执行的操作也会被拒绝。无法停用当前管理设备自身。
- 改密码：校验旧密码，结束该账号其他会话；保留设备登记及本地密钥。
- 当前没有找回密码、邮箱恢复或丢失最后管理设备后的自助恢复。建议另行登记一台可信管理设备。只知道密码的新浏览器仍需管理设备确认。
- 被停用设备不能靠再次输入密码恢复；后续重新加入需要新设备密钥及重新配对，不提供自动恢复按钮。
- 旧版未注册浏览器仍可使用原有本地配对模式。已登记到账号的设备必须登录且具备有效审批角色才能签署。

完整语义参见 [撤销场景](REVOCATION_SCENARIOS.md)。指纹确认仍为演示交互，密码、签名与服务端校验实际执行。

## 安全与实现范围

密码使用独立随机盐及 scrypt（N=32768、r=8、p=3）保存，不保存明文。登录具有速率限制和计算并发限制。12 小时会话使用 HttpOnly、SameSite=Strict Cookie，HTTPS 下设置 Secure；服务端只存会话令牌摘要。修改操作校验 Origin，关键设备操作还要求一次性挑战及设备签名。

当前反向代理下来源地址可能统一为本机，因此按地址限流可能影响同时登录的多个用户；这是小规模 Demo，尚未实现受信代理客户端地址配置。未提供企业 SSO、生产级恢复、跨端加密审批历史同步或外部设备凭证标准互通。

## 验证

`npm test`：22 项自动测试，覆盖账号隔离、错误密码、重复挑战、只读限制、待确认设备、撤销会话与已批准操作、用户撤销和 Agent 退出。

`node tests/accounts-browser.mjs`：两套隔离浏览器实测注册、配对、另一端登录、管理确认、目录共享、只读限制、停用、退出及手机布局。

`npm run test:browser`：原审批、修改、凭证出示、执行回执、自动规则和 CLI 全流程回归。
